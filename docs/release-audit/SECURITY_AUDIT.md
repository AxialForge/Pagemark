Auditor: security/release-engineering auditor. Commit `045e814` (tag `v0.7.0`). Finding IDs PGM-200..PGM-217 (permanent).
Evidence key: `script <name>` (in `docs/release-audit/scripts/`), `auditor` (run by me this session), `code <file:line>` (read only).
No `lib/`, `test/`, `android/`, `pubspec.yaml` or existing docs were modified. No emulator/adb, no NAS, `key.properties` and the keystore were not read.

Both HIGH findings share one root cause: `FlutterSecureStorage()` is constructed with default options (`lock.dart:14`, `backup.dart:142`) and in
`flutter_secure_storage` 11.2.0 the Android default is `resetOnError = true`, i.e. if the Keystore-wrapped key cannot decrypt, **every** stored key is
silently deleted. Everything that protects the vault (mode, pin_hash, rec_hash, fails, lock_until) and the backup passphrase (`bk_pass`) lives there.

## Findings

### PGM-200 HIGH - Lost secure storage turns the PIN/app lock into "choose a new PIN" and opens the vault
- **Repro (script):** `flutter test docs/release-audit/scripts/pgm200_securestorage_loss_test.dart` - with empty secure storage the `LockGate` shows "Set a PIN" (and `LockService.mode()` is null) instead of refusing. Passing the dialog calls `onUnlock`.
- **Expected:** a library that has locked books and a configured lock must never fall back to the "first-time setup" state without the old credential; at minimum the app should detect "locked books exist but no lock config" and stay closed (or force Restore/Reset with a loud warning).
- **Actual:** `LockService.mode()` returns null -> `LockGate` (lock_ui.dart:195-205) offers "Set a PIN" / device lock and unlocks. The whole-app lock (`appLockEnabled` is a plain SharedPreferences bool) shows the same gate, so it is also bypassed.
- **Trigger:** any secure-storage reset: Keystore key invalidation / corruption on some OEMs, OS upgrade quirks, key-store wipe. `allowBackup=false` removes the restore-from-backup trigger but not the others. Likelihood low-to-moderate, consequence total (vault and app lock open to whoever holds the phone).
- **Cause:** `FlutterSecureStorage()` default options (`lock.dart:14`); no "locked books exist" cross-check; lock state is only in secure storage. The package default `resetOnError: true` is at `flutter_secure_storage-11.2.0/lib/options/android_options.dart:51`.
- **Suggested fix:** pass `AndroidOptions(resetOnError: false)` and treat a read exception as "locked, unknown" (fail closed, show "secure storage unavailable"); keep a non-secret marker in SharedPreferences/DB (`lock_configured=true`) so "marker set but mode null" is detected and routes to an explicit recovery screen (recovery code can no longer work, so the only honest path is "erase locked library or keep it unreadable"). Add a test next to `data_safety_test.dart`.
- **Verify:** the script above must fail (gate must not show "Set a PIN" when the marker is set).

### PGM-202 HIGH - Same wipe silently downgrades scheduled Drive backups to plaintext, locked books included
- **Repro (code):** set a passphrase (`bk_pass`), enable automatic backup, lose secure storage (see PGM-200). `DriveBackup.run` (backup.dart:158-176) reads `passphrase()`, gets null and uploads `pagemark-*.zip/.sqlite` unencrypted; the signature `...|plain` differs from `...|enc`, so it re-uploads immediately. No notification, no `bk_err`; the only trace is the toggle showing "off" on the backup page (`backup_page.dart:93`).
- **Expected:** a backup job that was configured as encrypted must fail closed ("passphrase missing - open Pagemark") rather than upload plaintext; the user said "locked books are in every backup".
- **Impact:** privacy: the entire library incl. locked books, quotes, thoughts leaves the phone in the clear to Google Drive; the 5 retained copies rotate out the encrypted ones.
- **Cause:** "encrypted" is not a stored setting, it is the *presence* of `bk_pass` (backup.dart:146-148, 161-176).
- **Fix:** persist `bk_encrypt=true` in SharedPreferences when a passphrase is set; in `run()` if `bk_encrypt` and no passphrase -> throw `BackupAuthException` (notify: "your backup passphrase is missing; backups are paused").
- **Verify:** unit test with `FlutterSecureStorage.setMockInitialValues({})` + `bk_encrypt=true` expects an exception and no `files.create` call.

### PGM-201 MEDIUM - Diagnostics log can contain book titles / thoughts (promise "never" is false on failure paths)
- **Evidence:** `script pgm201_log_param_leak_test.dart` prints `SqliteException(2067)... Causing statement: INSERT INTO "shelves" ("name") VALUES (?), parameters: MY-SECRET-SHELF-NAME`. sqlite3 3.x `SqliteException.toString()` embeds bound parameters; Drift wraps them. Call sites that interpolate the raw exception: `import_ui.dart:42,55` (Log.e), `backup.dart:46,201`, `log.dart:75,79` (global Flutter/async handlers), `lookup.dart:87`.
- **Impact:** an import/write failure (or any uncaught DB error, including on locked books) writes titles/authors/notes/thoughts into `pagemark.log`; Settings -> Diagnostics tells the user to **Copy** it when asking for help, and CLAUDE.md/PRIVACY.md/manual §15 state it never holds book data.
- **Fix:** in `Log.e/w` redact: log `e.runtimeType` plus `SqliteException.message/resultCode` only; strip anything after "Causing statement". Add a test that logs the exception above and asserts the secret is absent.

### PGM-203 MEDIUM - Plaintext copies of exports/backups survive in cache sub-folders that the "wipe" never touches
- **Evidence:** `code share_plus-13.3.1/.../Share.kt:239,297-304` copies every shared file into `cacheDir/share_plus/<name>`; it is deleted only by the *next* share call (`:119,287`). `file_picker` (android_file_picker-2.0.1 `FileUtils.kt:713-757`) copies every picked file (restore backup, import CSV) into `cacheDir/file_picker/<ts>/`; it is cleared only by `clearTemporaryFiles()`, which the app never calls (`grep clearTemporaryFiles lib` = empty). `cleanTempExports` (privacy.dart:30-38) only iterates top-level **files** in the cache dir.
- **Impact:** an unencrypted "Export database file" (includes locked books, thoughts) or a decrypted/picked backup stays readable in app cache indefinitely, contradicting manual §8 ("temporary export files are deleted") and ROUNDING_OUT IB-10 "fixed". Private app storage, so exposure = root/adb on rooted/debug phones, device backups of cache excluded; still a stated guarantee that is not met.
- **Fix:** in `cleanTempExports` also delete `cache/share_plus` and `cache/file_picker` recursively, and call it right after share/restore/import complete (not only on relock). **Verify:** device: export unencrypted DB, `adb shell run-as` not available on release; instead add a unit test around the helper with a temp dir.
- *Not tested on a device (adb off-limits to me); behaviour read from plugin source.*

### PGM-204 MEDIUM - FLAG_SECURE can be dropped on `paused` for the hidden-tab vault (needs device check)
- **Evidence:** `code ui.dart:172-176` - `VaultPage.dispose()` calls `Secure.set(false)` unconditionally when it was unlocked; `didChangeAppLifecycleState(paused)` (`ui.dart:183-187`) with delay 0 runs `wipeLockedTraces()` -> `popUntil(first)` -> dispose. The documented gotcha (CLAUDE.md "FLAG_SECURE ordering") says the flag must stay on until `resumed`; the tab version honours it (`ui.dart:96,101`), the hidden-tab version clears it immediately and does not check `appLocked`.
- **Impact:** between pause and the recents snapshot the vault screen may be captured unprotected (pop animation). Unverified - the device auditor should long-press-"Library" vault -> Home -> Recents and screenshot the card.
- **Fix:** drop `Secure.set(false)` from `VaultPage.dispose` (let `resumed` in Home clear it) or guard with `appLocked`.

### LOW findings
- **PGM-205 LOW (crypto parameters).** PBKDF2-HMAC-SHA256 at 150,000 iterations for the PIN (lock.dart:16), recovery code, and backup container (crypto_backup.dart:16). OWASP 2023 guidance is 600,000 for SHA-256. Backup passphrase minimum is 8 characters (`backup_page.dart:137`, `ui.dart:1272`), so a stolen Drive `.pgbak` is brute-forceable offline for weak passphrases. Mitigations present: random 16-byte salt per file (so key differs per file -> the random 96-bit GCM nonce cannot repeat under one key), constant-time compare (`lock.dart:155-162`), authenticated header-less GCM (wrong passphrase/tamper -> `WrongPassphrase`). Suggest 600k + store the iteration count in the container (new magic `PGMKENC2`) and a 10+ char/strength meter. `code`.
- **PGM-206 LOW (clock).** Lockout (`lock_until`) and the lock-after-delay (`app_lock.dart:62-66`, `ui.dart:95-103`) use wall-clock `DateTime.now()`. Setting the system clock forward clears a PIN lockout; setting it back keeps the vault open past the delay. Needs the phone unlocked + Settings access, so LOW. Use `Stopwatch`/monotonic elapsed where possible. `code lock.dart:77-81,95-102`.
- **PGM-207 LOW ("Remove lock").** `Remove lock` (ui.dart:1344-1350) clears the credentials but leaves `app_lock` (prefs) true, so the next launch shows a gate that offers "Set a PIN" to anyone; and locked books stay in the vault open to whoever sets the new PIN (subtitle says so). By design for the vault, but the whole-app lock should be switched off with it, and the removal confirmation should say the locked books will be readable by anyone. Related: ROUNDING_OUT IB-16 listed as fixed. `code`.
- **PGM-208 LOW (clipboard).** The recovery code dialog has a **Copy** button (`lock_ui.dart:84`) that puts the 80-bit PIN-bypass secret on the system clipboard and never clears it (clipboard history/keyboards/other apps pre-Android 13 can read it). Also quotes copy to the clipboard by design. Suggest clearing after ~60 s or marking `ClipDescription.EXTRA_IS_SENSITIVE`. `code`.
- **PGM-209 LOW (updater hardening).** `Updater.download` (updater.dart:133-156) takes `browser_download_url` from the JSON with no scheme/host check, follows redirects, and silently skips the SHA-256 check when the asset has no `digest` (updater.dart:117). Trust model (INFO): digest and file come from the same GitHub channel, so the digest only detects corruption, not a hostile release; the real integrity guarantee is Android refusing an APK signed with a different key than the installed one - this holds because all releases share certificate SHA-1 `39:04:...F7` (PGM-220). Downgrade is not possible (`compareVersions`, `available` needs latest > current; Android also refuses a lower versionCode). Suggest: require `https` + host in {github.com, objects.githubusercontent.com, release-assets.githubusercontent.com}, and show "unverified" when no digest. `code`.
- **PGM-210 LOW (backup temp files on failure).** `DriveBackup.run` deletes `snap`/`upload` only on success (backup.dart:186-189); on any error the plaintext snapshot (with locked books) stays in cache until the next foreground launch (`ui.dart:62`). Wrap in `try/finally`. `code`.
- **PGM-211 LOW (public-repo privacy).** The repo is PUBLIC (`gh repo view`): `tool/backup-to-nas.ps1:15` and `CLAUDE.md:99` publish the home NAS address `\\192.168.1.204\Apocrypha_Main_Pool\Libary_Pool\APP Projects\PageMark`, and the script's README text states that the signing keystore **and `key.properties` with plaintext passwords** are kept on that share ("the ONLY copy outside this PC"). RFC1918 address, no credentials in the repo, so LOW; it tells an attacker where the release key lives. Also in history (`git log -S"Apocrypha"`: 254b1b5, 2a12a91), so removal needs a history rewrite - not recommended; consider parameterising the default path (env var) going forward. `LICENSE:3` carries the owner's full name (owner's call). `script pgm200_apk_scan.py` + `auditor` git grep.
- **PGM-213 LOW (documentation-build switch).** `Secure._docBuild = bool.fromEnvironment('PAGEMARK_SCREENSHOTS')` (privacy.dart:19) is compile-time only (not settable at runtime, no `--dart-define-from-file` in repo). I could not prove the shipped APK was built without it: the constant is folded so neither the name nor the value appears in `libapp.so` (`script pgm200_apk_scan.py`: name found only in the bundled CHANGELOG text). There is no release script/CI guard to make shipping it impossible. Verify behaviourally on a device (locked screen screenshot must be black) and add a `tool/` release script that refuses `PAGEMARK_SCREENSHOTS` in its define list.

- **PGM-216 INFO - manifest review (release APK `Pagemark-0.7.0-arm64.apk`, `aapt2 dump xmltree`).** `allowBackup=false`, `fullBackupContent=false`, `dataExtractionRules` excludes root/file/database/sharedpref/external for cloud-backup and device-transfer; not debuggable; no `usesCleartextTraffic` and no network-security-config (targetSdk 36 default = cleartext blocked); `extractNativeLibs=false`. ## Crypto review notes
| Item | Result |
|---|---|
| PIN hash | PBKDF2-HMAC-SHA256, 150k, random 16-byte salt per `setPin`; legacy SHA-256 hash auto-upgraded (lock.dart:117-127) |
| Compare | length check then XOR-accumulate: constant time per length (fine) |
| Recovery code | 16 chars from 32-symbol alphabet = 80 bits via `Random.secure`; hashed with its own salt; guesses share the PIN `fails` counter and lockout (lock.dart:130-141) - good |
| Lockout | 5 free misses, then every further miss locks 30 s, doubling each 5 misses, cap 3600 s (matches manual §8 wording closely: the first 30 s lock applies to each of misses 5-9). Worst-case exhaustive search of a 4-digit PIN ~80 days |
| PIN length | 4-12 digits (`setupPin`, `_forgot`); 4-digit PINs are weak only if secure storage is extracted |
| Backup container | `PGMKENC1 | salt16 | nonce12 | ct | tag16`, fresh salt+nonce per file, key per file |
| Plain DB at rest | not encrypted - owner decision 2026-10-12, do not re-propose (PGM-214 note only) |
| Secure storage options | defaults (see PGM-200) |
